# API Automation Framework

This project is a lightweight API test automation framework built with Python, pytest, and the requests library. It is designed to automate CRUD operations against a sample REST API and generate clear test reports and logs.

## What this framework follows

This repository follows a simple and modular test automation approach:

- Use pytest as the test runner
- Use requests for HTTP calls
- Keep test data separate from test logic
- Centralize API request handling in one reusable client
- Log request/response details for debugging
- Generate HTML reports after test execution

In short, this is a pytest-based API automation framework with a clean, maintainable structure for testing REST endpoints.

## Framework structure

```text
API_AUTOMATION_FRAMEWORK/
│
├── conftest.py              # Pytest hooks and shared fixtures
├── pytest.ini               # Pytest configuration and report settings
├── requirements.txt         # Python dependencies
├── testdata/                # JSON test payloads
│   └── activity.json
├── tests/                   # Test cases
│   └── test_getuser.py
├── utils/                   # Reusable helper modules
│   ├── api_client.py        # API wrapper for GET/POST/PUT/DELETE
│   └── logger.py            # Logging configuration
├── reports/                 # HTML reports generated by pytest
├── logs/                    # Log files
└── README.md                # Project documentation
```

## How the framework is managed

### 1. Test execution
Pytest is the core engine for running tests. It handles:
- test discovery
- assertions
- fixtures
- test reporting

### 2. API calls
All API interactions are managed through a reusable client in [utils/api_client.py](utils/api_client.py). This avoids duplicate HTTP code and keeps tests clean.

### 3. Test data
Test payloads are stored in JSON files under [testdata/activity.json](testdata/activity.json). This makes the tests easier to maintain and update.

### 4. Logging
The framework logs request details, status codes, response time, and response bodies using the logger module in [utils/logger.py](utils/logger.py).

### 5. Reporting
Pytest HTML reports are generated automatically and stored in the [reports](reports) folder.

Make sure Python is installed on your system.

## Setup instructions

### 1. Create and activate a virtual environment

On Windows PowerShell:

```powershell
python -m venv arvind_venv
.\arvind_venv\Scripts\Activate.ps1
```

### 2. Install dependencies

```powershell
pip install -r requirements.txt
```

## Run tests

Run the complete test suite:

```powershell
pytest
```

Run a specific test file:

```powershell
pytest tests/test_getuser.py
```

## Test coverage

The current test suite includes:

## Reports and logs

- HTML reports are stored in the [reports](reports) folder
- Execution logs are stored in the [logs](logs) folder

## Example of current test flow

1. A test case is written in [tests/test_getuser.py](tests/test_getuser.py)
2. The test uses the reusable API client from [utils/api_client.py](utils/api_client.py)
3. The request is sent to the target API
4. The response is validated using assertions
5. The result is logged and reported
